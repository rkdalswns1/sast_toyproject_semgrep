# UI Design Handoff

UI 디자인은 Phase 1과 Phase 2의 선행조건이 아니다. 로그인 및 실제 화면 구현이 시작되는 Phase 3 전에 디자인을 확정한다.

## Required Screens

1. 로그인
2. 프로젝트 목록
3. 프로젝트 생성
4. 프로젝트 수정
5. 프로젝트 상세
6. 프로젝트 사용자 할당
7. ZIP 업로드 및 분석 실행
8. 분석 이력 및 실행 상태
9. Finding 목록 및 필터
10. Finding 상세
11. KISA 규칙 카탈로그
12. 진단 항목 등록·수정 — pen.dev 승인 후 구현
13. KISA 카탈로그 상세 — pen.dev 승인 후 구현

## Required States

- 기본 상태
- 데이터가 없는 상태
- 입력 검증 오류
- 분석 대기
- 분석 진행 중
- 분석 완료
- 분석 실패
- 접근 권한 없음
- 서버 오류

## Design Handoff Files

pen.dev에서 작성한 디자인은 프로젝트의 `design/` 디렉터리에 저장한다.

가능하면 디자인 도구 원본 파일과 화면별 PNG 또는 PDF export, 사용한 색상·글꼴·간격, 버튼·입력창·표·상태 배지 스타일을 함께 제공한다.

원본 파일을 Codex가 직접 해석하지 못하더라도 PNG 또는 PDF를 구현 기준으로 사용할 수 있어야 한다.

## Implementation Boundaries

- Jinja2 서버 렌더링 구조를 유지한다.
- 디자인 때문에 React 또는 Next.js를 추가하지 않는다.
- 별도의 SPA 구조를 추가하지 않는다.
- 공통 디자인은 재사용 가능한 CSS로 구현한다.
- 디자인은 `docs/routes.md`의 경로를 변경하지 않는다.
- 디자인은 인증 및 권한 정책을 변경하지 않는다.
- 사용자 계정 식별자는 `@company.com` 사내 이메일을 사용하며 이름·별도 연락처 필드는 추가하지 않는다.
- 사용자 생성은 회사 이메일, 초기 password, password 확인, `SUPER_ADMIN`·`PROJECT_MANAGER`·`USER` 역할, 활성 상태를 입력받는다.
- 신규 계정은 최초 로그인 후 현재 초기 비밀번호, 새 비밀번호와 확인값을 입력하는 비밀번호 변경 화면을 반드시 거친다. 로그인 사용자는 같은 화면에서 자신의 비밀번호를 변경할 수 있다.
- 관리자가 다른 사용자의 비밀번호를 초기화하는 화면은 제공하지 않는다.
- ZIP 업로드 제한 표기는 압축 파일 20 MiB, 압축 해제 전체 100 MiB로 구분한다.
- 프로젝트 생성·수정 화면은 기준 언어 선택과 `지원 언어 자동 감지 및 통합 분석` 선택을 제공한다. 프로젝트·분석 상세에는 단일/통합 모드와 실제 감지·분석 언어를 텍스트로 표시하며 새 화면은 추가하지 않는다.
- 분석 실행 중 화면은 HTTP 요청이 끝날 때까지의 단순 대기 화면이며, 진행률·취소·실시간 갱신 기능을 전제하지 않는다.
- 프로젝트 생성, 사용자·규칙 관리 버튼은 SUPER_ADMIN에게만 표시한다. 프로젝트 수정·사용자 배정·ZIP 업로드·분석 실행 버튼은 SUPER_ADMIN과 해당 프로젝트의 PROJECT_MANAGER에게 표시한다. USER는 프로젝트와 분석 결과를 읽기 전용으로 조회한다.
- USER에게 분석 실패 상태는 표시할 수 있지만 내부 분석 오류 원문은 표시하지 않는다.
- Finding 목록과 상세에는 조치 상태를 표시한다. 상세 화면에서 SUPER_ADMIN과 담당 PROJECT_MANAGER에게만 상태·의견 변경 폼을 보여주고 USER는 최신 상태, 의견, 변경 계정과 시각을 읽기 전용으로 본다.
- Finding 목록에는 담당자·조치 기한과 기한 초과 표시 및 필터를 추가한다. 상세의 기존 조치 관리 카드에서 SUPER_ADMIN과 담당 PROJECT_MANAGER만 프로젝트의 활성 할당 사용자를 담당자로 선택하고 날짜를 입력하며, USER는 같은 정보를 읽기 전용으로 본다.
- Finding 상세의 기존 카드 흐름에 재검증 실행 버튼과 최신순 이력 표를 추가한다. 실행 버튼은 SUPER_ADMIN과 담당 PROJECT_MANAGER에게만 표시하고 USER는 결과·실행 계정·시각과 새 분석 링크를 읽기 전용으로 본다. 별도 재검증 화면은 만들지 않는다.
- 분석 이력과 상세에는 분석을 실행한 계정 식별자를 표시한다.
- ZIP 업로드 폼에는 선택 입력인 소스 버전, 배포 버전과 설명을 기존 카드 안에 추가한다. 프로젝트 상세은 최신 값을, 분석 이력·상세는 실행 시점의 값을 표시하며 별도 화면은 추가하지 않는다.
- 프로젝트 상세의 ZIP 카드 다음에 공개 GitHub 저장소 URL, 선택 ref와 동일한 소스 메타데이터를 입력하는 수집 폼을 추가한다. 공개 저장소만 지원한다는 안내와 최신 저장소 URL·ref·commit을 표시하며 별도 화면은 추가하지 않는다.
- 프로젝트 상세의 기존 업로드 카드 다음에 `분석 전 소스 확인` 영역을 두고 최신 ZIP 파일명, 업로드 시각, 실제 파일 수·크기, 감지 언어와 최대 20개의 상대 파일 경로를 표시한다. 모든 프로젝트 접근 역할이 조회하되 분석 실행 버튼은 기존 운영 역할에게만 표시하며 소스 본문 미리보기와 다운로드는 추가하지 않는다.
- 분석 상세 헤더에 `CSV 보고서`와 `PDF 보고서` 다운로드 버튼을 배치한다. 새 보고서 화면은 만들지 않고 기존 버튼 스타일을 재사용한다.
- Finding 상세의 메타데이터에 주요 CWE와 매핑 확신 수준을 표시하고 MITRE 공식 문서 링크와 관련 CWE를 제공한다. 기존 권고 영역은 DiagnosticRule에서 스냅샷한 조치 권고를 표시한다.
- 프로젝트 상세 헤더에는 SUPER_ADMIN에게만 빨간색 `프로젝트 삭제` 버튼을 표시하며 제출 전에 삭제 확인 창을 띄운다.
- 프로젝트 생성·수정 폼에는 SUPER_ADMIN 전용 선택 입력 만료일을 추가하고 입력 시점의 다음 날부터 선택하게 한다. 오늘·과거 날짜 제출은 폼 오류로 안내하며 목록·상세에는 설정된 만료일을 표시한다. 만료 프로젝트 전용 화면은 추가하지 않는다.
- 분석 상세의 수집 결과에는 엔진 탐지, 저장 Finding과 함께 오탐 자동 제외 건수를 표시한다.
- 분석 상세의 오탐 자동 제외 건수는 실행별 읽기 전용 내역 화면으로 연결한다. 내역은 KISA·규칙·언어·상대 위치·메시지와 최초 오탐 판정자·시각·의견을 표시하되 코드·지문·원본 JSON은 표시하지 않는다.
