# pen.dev prompts for SFR-012 and SFR-013

기존 `design/pencil-new.pen`의 21개 데스크톱 프레임, 색상, 글꼴, 여백, 카드, 테이블, 버튼, 입력창, 배지 스타일을 그대로 유지한다. 기존 프레임을 삭제하거나 복제하지 말고 아래 신규 프레임만 추가한다. React나 모바일 앱 구조를 전제하지 않고 FastAPI + Jinja2 서버 렌더링 화면으로 설계한다.

## SFR-012 — 진단 항목 공통 등록

```text
현재 .pen 파일의 기존 디자인 시스템을 사용해서 ADMIN 전용 “진단 항목 등록”과 “진단 항목 수정” 데스크톱 화면 2개를 추가해줘.

목적:
- 새로운 진단 항목을 공통 형식으로 등록한다.
- KISA 카탈로그 항목과 실제 Semgrep 규칙 매핑을 구분해서 보여준다.
- raw YAML을 웹에서 직접 편집하거나 실행하지 않는다. 배포된 Semgrep rule ID와 메타데이터만 등록한다.

화면 1: 진단 항목 등록
- 페이지 제목: 진단 항목 등록
- 상단 breadcrumb: KISA 규칙 > 진단 항목 등록
- ADMIN 표시와 목록으로 돌아가기 버튼
- 입력 필드:
  1. KISA 카탈로그 항목 선택 — KISA ID, 분류, 항목 번호, 명칭을 함께 검색할 수 있는 select
  2. 진단 항목명
  3. 설명
  4. 참조 정보 또는 공식 문서 링크
  5. 기본 심각도 — INFO, LOW, MEDIUM, HIGH, CRITICAL
  6. 구현 상태 — IMPLEMENTED, PARTIAL, NOT_IMPLEMENTED
  7. 활성 여부
  8. 지원 언어 — Java, JavaScript, Python 체크박스
  9. 언어별 Semgrep rule ID — 선택한 언어별 한 줄 입력, 예: kisa-2021-sql-injection-java
- 하단 버튼: 취소, 진단 항목 등록
- 도움말: “Semgrep YAML은 검토 후 별도 배포하며 이 화면에서는 실행 코드를 입력하지 않습니다.”

화면 2: 진단 항목 수정
- 등록 화면과 동일한 구조
- KISA ID, 분류, 항목 번호는 읽기 전용
- 현재 값이 채워진 상태
- 변경 저장 버튼과 비활성화 버튼
- 물리 삭제 버튼은 만들지 않는다.
- 해당 항목을 참조하는 Finding 수와 마지막 수정 시각을 요약 카드로 표시

필수 상태를 같은 프레임 안의 컴포넌트 예시 또는 인접 variant로 표현:
- 필수값 누락
- 중복 Semgrep rule ID
- 지원 언어를 선택했지만 해당 언어 rule ID가 없는 오류
- 저장 성공 알림
- 비활성 항목 경고
- 일반 USER 접근 권한 없음 상태

접근성:
- label과 입력창 연결
- 키보드 포커스가 명확해야 함
- 오류는 빨간색만 쓰지 말고 오류 문구를 함께 표시
- IMPLEMENTED/PARTIAL/NOT_IMPLEMENTED는 색상과 텍스트를 함께 표시
```

## SFR-013 — KISA 49개 카탈로그 조회

```text
현재 .pen 파일의 기존 디자인 시스템을 사용해서 “KISA 소프트웨어 개발보안 49개 카탈로그 목록”과 “KISA 카탈로그 상세” 데스크톱 화면 2개를 추가해줘.

권한:
- ADMIN과 USER 모두 카탈로그를 조회할 수 있다.
- 진단 항목 등록·수정 버튼은 ADMIN에게만 표시한다.
- USER 화면에는 수정, 비활성화, 등록 버튼이 없어야 한다.

화면 1: KISA 카탈로그 목록
- 페이지 제목: KISA 개발보안 진단 기준
- 설명: “KISA 소프트웨어 보안약점 진단가이드(2021) 구현단계 49개 항목”
- 상단 요약 카드:
  1. 전체 49개
  2. IMPLEMENTED 개수
  3. PARTIAL 개수
  4. NOT_IMPLEMENTED 개수
- 검색 및 필터:
  - KISA ID 또는 명칭 검색
  - 분류 필터
  - 구현 상태 필터
  - 지원 언어 필터 — Java, JavaScript, Python
  - 활성 여부 필터
- 테이블 열:
  - KISA ID
  - 분류
  - 항목 번호
  - 명칭
  - 기본 심각도
  - 구현 상태
  - 지원 언어 배지
  - 활성 상태
  - 상세 링크
- ADMIN 화면 상단에 “진단 항목 등록” 버튼
- 페이지네이션은 49개 규모에 맞게 단순하게 설계하거나 전체 표시 가능

화면 2: KISA 카탈로그 상세
- breadcrumb: KISA 규칙 > KISA ID
- 제목: 보안약점 명칭
- 메타데이터 카드:
  - KISA ID
  - 분류
  - 항목 번호
  - 기본 심각도
  - 구현 상태
  - 활성 여부
- 본문 섹션:
  1. 설명
  2. 조치 권고
  3. 참조 정보
  4. 지원 언어와 언어별 Semgrep rule ID
  5. 연결된 최근 Finding 수
- ADMIN에게만 “진단 항목 수정” 버튼 표시
- USER에게는 읽기 전용임을 짧게 표시

필수 상태:
- 전체 목록 기본 상태
- 검색 결과 없음
- NOT_IMPLEMENTED 항목 상세
- 비활성 항목 상세
- 서버 오류
- 일반 USER 읽기 전용 상태

주의:
- 49개 항목명을 임의로 새로 만들지 말고 화면 예시는 현재 프로젝트 카탈로그의 실제 명칭만 사용한다.
- 기존 프로젝트/분석/Finding 화면의 헤더, 카드, 테이블, 배지 스타일과 시각적으로 이어져야 한다.
- 새 사이드바나 완전히 다른 디자인 시스템을 만들지 않는다.
```
