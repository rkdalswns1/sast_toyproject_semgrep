Communication job

By the end, bootcamp instructors acting as a non-technical RFP customer should understand that the MVP connects the full SAST workflow with defensible security decisions, know the current verified scope without inflated claims, and see a realistic path to the final presentation.

Deck structure

1. Minimal title
2. End-to-end MVP flow
3. Authentication and authorization rationale
4. Project-level access boundary
5. ZIP defenses and per-run workspace isolation
6. Semgrep normalization, provenance, and Finding history
7. KISA catalog versus actual automatic detection coverage
8. Midpoint verification, remaining schedule, and demo sequence
9. Appendix: requirement traceability by feature cluster
10. Appendix: test/quality evidence and likely Q&A

Visual direction

- 16:9, Korean, Noto Sans CJK KR
- SecureScan navy (#0B2236), blue (#1F6EA5), pale blue (#EAF3F9), white, and restrained semantic colors
- Flat technical editorial layout rather than dashboard-card collage
- Four approved UI images from design/export.pdf
- Requirement IDs are evidence tags, never the main reading order
- Main deck supports 6-7 minutes of speaking plus a 2-3 minute demonstration
